# Инструкция: настройка и запуск мессенджера (Supabase)

Этот мессенджер написан на чистом HTML/CSS/JS и использует **Supabase**
(Postgres + Auth + Realtime) как базу данных.

Бесплатный тариф Supabase покрывает старт с большим запасом.

---

## Шаг 1. Создать проект Supabase

1. Откройте https://supabase.com/dashboard
2. Зарегистрируйтесь / войдите (можно через GitHub)
3. Нажмите **New project**
4. Выберите организацию (или создайте), введите:
   - Name: например `messenger`
   - Database Password: придумайте надёжный пароль и **сохраните его** (он не для входа в чат, а для прямого доступа к Postgres)
   - Region: выберите ближайший к вам
5. Нажмите **Create new project**, подождите 1-2 минуты инициализации

## Шаг 2. Выполнить SQL-схему

1. В левом меню откройте **SQL Editor**
2. Нажмите **New query**
3. Откройте файл **`schema.sql`** из этого проекта, скопируйте его содержимое целиком
4. Вставьте в редактор и нажмите **Run** (или Ctrl+Enter)
5. Должно появиться сообщение "Success. No rows returned"

Проверьте: в левом меню откройте **Table Editor** — там должны появиться
4 таблицы: `profiles`, `chats`, `chat_members`, `messages`.

> Этот SQL-скрипт уже включает:
> - создание всех таблиц
> - Row Level Security (RLS) политики — это аналог правил безопасности,
>   они гарантируют, что пользователи видят только свои чаты и сообщения
> - автоматический триггер, который создаёт профиль пользователя при регистрации
> - включение Realtime для чатов и сообщений

## Шаг 3. Настроить Authentication

1. В левом меню откройте **Authentication → Providers**
2. Убедитесь, что **Email** включён (включён по умолчанию)
3. (Опционально) Откройте **Authentication → Settings**:
   - Если хотите, чтобы пользователи могли входить **сразу после
     регистрации без подтверждения почты** — отключите
     **"Confirm email"** в разделе Email Auth. Это удобно для тестов
     и небольших проектов.
   - Если оставить включённым — пользователям будут приходить письма
     с подтверждением (письма шлёт сам Supabase, ничего настраивать
     дополнительно не нужно, но лимит — 3-4 письма в час на бесплатном тарифе)

## Шаг 4. Получить ключи API

1. Откройте **Project Settings** (шестерёнка в левом меню) → **API**
2. Скопируйте:
   - **Project URL** (вида `https://abcdefgh.supabase.co`)
   - **anon public** key (длинная строка в разделе "Project API keys")
3. Откройте файл **`supabase-config.js`** из этого проекта и вставьте оба значения:

```js
const SUPABASE_URL = "https://abcdefgh.supabase.co";
const SUPABASE_ANON_KEY = "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...";
```

> Ключ `anon public` безопасно использовать в открытом клиентском коде —
> он специально для этого предназначен. Реальная защита данных
> обеспечивается RLS-политиками на стороне базы (которые мы уже создали
> в Шаге 2), а не секретностью этого ключа.

## Шаг 5. Запустить локально (для проверки)

Открыть `index.html` через `file://` не сработает (браузер блокирует часть
запросов для локальных файлов). Нужен простой локальный сервер:

**Вариант А — если у вас установлен Python:**
```
cd путь/до/папки/messenger-supabase
python -m http.server 8000
```
Откройте http://localhost:8000

**Вариант Б — расширение VS Code "Live Server"** — правой кнопкой
по index.html → "Open with Live Server"

## Шаг 6. Разместить на хостинге (для других людей)

Самый простой способ — статический хостинг. Подойдёт любой из:

### Netlify (бесплатно, проще всего)
1. https://app.netlify.com/ → зарегистрируйтесь
2. Перетащите папку `messenger-supabase` прямо в браузер на странице Netlify
   (drag-and-drop deploy)
3. Получите ссылку вида `https://random-name.netlify.app`

### Vercel
```
npm install -g vercel
cd путь/до/папки/messenger-supabase
vercel
```

### GitHub Pages
1. Создайте репозиторий на GitHub, загрузите туда все файлы
2. Settings → Pages → Source: выберите ветку `main` → Save
3. Получите ссылку вида `https://username.github.io/repo-name`

Во всех случаях достаточно загрузить 4 файла:
`index.html`, `style.css`, `app.js`, `supabase-config.js`

## Шаг 7. (Важно) Указать домен в настройках Supabase

После того, как сайт окажется на реальном домене (не localhost):

1. Supabase Dashboard → **Authentication → URL Configuration**
2. В поле **Site URL** укажите ваш домен (например `https://your-site.netlify.app`)
3. Это нужно, чтобы письма подтверждения email и сброса пароля
   ссылались на правильный адрес

## Структура файлов

```
messenger-supabase/
├── index.html          — разметка интерфейса
├── style.css            — стили (оформление в духе Telegram)
├── supabase-config.js   — ваши ключи Supabase (заполнить!)
├── app.js                — вся логика приложения
├── schema.sql            — SQL-схема БД, выполнить один раз в SQL Editor
└── SETUP.md              — этот файл
```

## Что реализовано

- ✅ Регистрация / вход по email + пароль
- ✅ Профиль с именем и аватаром (ссылка на изображение)
- ✅ Поиск пользователей по имени
- ✅ Личные чаты 1-на-1
- ✅ Группы с несколькими участниками
- ✅ Сообщения в реальном времени через Supabase Realtime
- ✅ Статус "онлайн/не в сети"
- ✅ Row Level Security — пользователи видят только свои чаты

- Push-уведомления

## Лимиты бесплатного тарифа Supabase

- 500 МБ базы данных
- 5 ГБ трафика/мес
- 50 000 monthly active users (через Auth)
- Проект "засыпает" после 7 дней неактивности на бесплатном тарифе
  (просыпается автоматически при первом запросе, но первый запрос
  будет на пару секунд медленнее)

Для небольшого/среднего сообщества этого достаточно с запасом.

## Частые проблемы

**"new row violates row-level security policy"** — значит RLS-политика
блокирует операцию. Проверьте, что вы выполнили весь `schema.sql`
целиком, без пропусков.

**Профиль не создаётся после регистрации** — проверьте в Supabase
Dashboard → Database → Triggers, что триггер `on_auth_user_created`
существует и активен.

**Realtime не работает (сообщения не приходят сами)** — проверьте
Database → Replication, что таблицы `messages` и `chats` добавлены
в публикацию `supabase_realtime` (это делает `schema.sql` автоматически,
но если меняли схему вручную — может потребоваться добавить заново).
